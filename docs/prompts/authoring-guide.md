# Форматы истории и главы

JSON главы импортируется в открытой главе конструктора. Пакет всей истории — через импорт в «Моих историях», после предварительной проверки конфликтов. Перед заменой скачайте резервную копию текущего содержимого.

Проверьте структуру и все сюжетные ветки, сохраните черновик и отправьте на модерацию. Импорт и сохранение не публикуют автоматически. «Просмотр сцен» показывает тексты и переходы; это не интерактивное прохождение.

Импорт исправленного JSON с тем же ключом в открытой главе сохраняет её серверную идентичность и версию. Если за это время глава изменилась в другой вкладке, сохранение отклоняется без потери текста. Скачайте JSON своих изменений и нажмите «Открыть актуальную версию»; отмена этого действия сохраняет текущий текст. Старый локальный черновик без сведений о версии также требует явного обновления перед записью.

## Форматы

**Глава:** объект с `key`, `title`, `description`, `genre`, `topic`, `completionStatus`, `version`, `startSceneId`, `variables`, `assets`, `scenes`. Ключи и ID сохраняются при редактировании. Не переименовывайте существующий ключ ради изменения названия: это другая идентичность, способная создать отдельный черновик.

Обложка самостоятельного сценария хранится в `metadata.coverUrl` и не заменяет фон стартовой сцены. Общая обложка истории с главами хранится в `collection.coverUrl`. Допустим существующий путь `/assets/...` или загрузка `/uploads/ID_ЭТОГО_ПРОИЗВЕДЕНИЯ/файл`; файл другого произведения не подходит, даже если автор тот же. Получите путь после загрузки в интерфейсе и передайте его в запрос. При изменении обложки сохраняйте остальные поля `metadata`, включая связи и входной контракт.

При загрузке интерфейс показывает безопасную центральную область и примеры кадрирования.
Растровое изображение уменьшается с сохранением пропорций до 1920×1080 и 500 КБ;
важные надписи и лица размещайте внутри зелёной области. WebP преобразуется в
JPEG/PNG, прозрачность сохраняется, GIF становится неподвижным изображением.
Готовый черновик или отдельную главу можно открыть кнопкой «Пройти черновик»:
это приватная проверка сохранённой редакции, без читательских сохранений и публикации.
У последовательной истории кнопка «Пройти историю» запускает все главы по порядку
с переносом глобальных переменных. После завершения главы доступна следующая;
«Начать сначала» сбрасывает всё проверочное прохождение. Изменения черновика во
время проверки появятся после нового открытия предпросмотра из «Моих историй».

**История:** пакет `{schemaVersion:1,kind:"fraerapp-work-package",root:{kind:"collection",key},scenarios:[...],collections:[...]}`. Его история в `collections` имеет `schemaVersion:2`, `type:"story"`, общие название/описание/обложку/жанр, `completionStatus`, упорядоченные `items`, `transitions:[]`. Каждый `item.target` ссылается по ключу на главу из `scenarios`; необязательный `season` подписывает последовательные главы. Это две разные версии схем: оболочка пакета 1, история 2.

Минимальный актуальный пример: [`../examples/serial-story-package.json`](../examples/serial-story-package.json). Полный пример с тремя главами, сезонами и текущими механиками: [`../../story-builder/scenarios/koshka-i-otkrytye-dveri.package.json`](../../story-builder/scenarios/koshka-i-otkrytye-dveri.package.json).

## Поддерживаемые возможности

### Страницы для чтения

Пишите полный текст логической сцены в `scene.text`. Читалка автоматически делит
его на страницы до 500 символов, а на маленьком экране — на более короткие части
по доступной высоте. Варианты ответа появляются после текста: до четырёх на
странице, при необходимости меньше. «Назад», «Далее» и «Ещё варианты» листают
только содержимое текущей сцены; параметры, эффекты и игровой прогресс меняются
при настоящем сюжетном выборе. Не добавляйте фиктивные сцены ради длины текста.

Под текстовым полем конструктора откройте «Страницы чтения», чтобы проверить
разбивку. Это ориентир по объёму; итоговое число страниц зависит от экрана и
подставленных переменных. Для подписи варианта рекомендуется до 100 символов;
длинная подпись получает подсказку, а её текст сохраняется полностью.
Импорт, сохранение и экспорт содержат исходную сцену целиком, без добавочных
полей или автоматически созданных переходов.

### Игровые механики

| Возможность | Контракт |
| --- | --- |
| Глобальные и локальные переменные | Число, строка, boolean; локальное имя перекрывает глобальное только внутри своей сцены; локальные значения сохраняются при повторном входе |
| Статистика и таймер | `{value,showInStats:true}`; `{type:"timer",value}` — числовое состояние без отсчёта по часам |
| Подстановки | `{{имя}}` в тексте сцены и подписи выбора; простой текст |
| Условия | `var/op/value`, `== != > >= < <=`, плоское И (AND), запасной `fallbackTarget` |
| Эффекты | `set`, числовой `inc` (включая отрицательный); эффекты выбора перед повторной проверкой перехода, эффекты сцены при каждом входе |
| Медиа | Общие и локальные assets, фон, аудио через music, fade-in; существующие `/assets/...` или разрешённые `/uploads/...` своей главы |
| Концовки | Завершение главы и несколько финалов последней главы; завершённость всей истории задаётся отдельно |
| Главы и сезоны | Упорядоченный список schema 2, подписи сезонов, автоматический перенос глобального состояния из конкретного прохождения |
| Дополнительные связи | JSON-совместимость `metadata.relations`, prequel/sequel/branch/related, independent/mapped и входные контракты number/string/boolean |
| Проверка и выпуск | Проверка ссылок/типов/путей/финалов, импорт черновика, предварительная проверка пакета, модерация |

Нет поддержки произвольного кода, OR/NOT-выражений, обратного отсчёта по часам, видео/спрайтов в проигрывателе или отдельного звукового триггера. Загружаемые файлы не возникают из текста промпта: ИИ должен использовать предоставленные пути либо оставить медиа пустым.

В последовательных главах schema 2 перенос глобальных значений автоматический, типы совпадающих имён должны оставаться совместимыми. Локальные значения не переносятся. `metadata.inputContract` и явное `stateTransfer` нужны только для отдельно заданных связей между произведениями, а не для обычного порядка глав.

## Исторические документы

`story-chapters-collections-codex.md` и `story-moderation-codex.md` — прежние задания на реализацию продукта, не инструкции для генерации сюжетного JSON. Вложенные коллекции schema 1 и старый пример `chapters-package.json` сохраняются для совместимости и проверки импорта; новые истории создаются по текущему формату schema 2.
